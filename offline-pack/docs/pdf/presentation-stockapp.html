StockApp — Présentation plateforme

Trois bénéfices clés pour l'entreprise

StockApp répond à des contraintes réelles de terrain : connectivité faible ou inexistante, souveraineté des données, besoin de couvrir tout le cycle commercial avec un seul outil cohérent.

🌐

1. Autonomie totale vis-à-vis d'Internet

Fonctionnement sans aucune dépendance réseau. Aucune donnée métier ne quitte le site — parfait pour la confidentialité et les zones à faible connectivité. Choix entre un PC unique, un réseau local ou le cloud, sans changer de code.

🔗

2. Couverture complète du cycle opérationnel

Un seul logiciel couvre les achats, le stock, les ventes, les paiements et la fiscalité — fini les tableurs multiples et la double saisie. Les données sont cohérentes entre elles.

🔐

3. Maîtrise et sécurité des données

Souveraineté des données : tout reste chez le client en mode offline. Sauvegardes planifiables, restauration maîtrisée. Authentification par utilisateur, profils différenciés.

💶

Bénéfices concrets sur le terrain

Gain de temps (fin de la double saisie), fiabilité (calculs automatiques des marges, TTC, stock), pilotage en temps réel, suivi fin de la trésorerie (impayés, échéances, avoirs).

4 · Architecture technique
StockApp — Présentation plateforme

Une application web 3 tiers, double mode

La force technique de StockApp réside dans sa capacité à basculer entre deux architectures — cloud et hors-ligne — sans modifier le code métier.

● Les trois couches applicatives

Couche 1 · Frontend
Interface web Next.js

Interface responsive consommée dans le navigateur. Poste fixe, portable, tablette, mobile. Thème clair/sombre.

Couche 2 · Backend
API Hono (Node / Bun)

Logique métier et règles de gestion exposées en API REST. Exécution Node.js ou Bun.

Couche 3 · Base cloud
Supabase (PostgreSQL)

Persistance managée pour le déploiement cloud (Vercel). Accès depuis n'importe où via tunnel sécurisé.

Couche 3 · Base locale
MySQL / MariaDB portable

Persistance 100 % locale pour le mode hors-ligne. Embarquée dans l'installeur Windows.

● Le double mode : cloud ou hors-ligne

Mode Cloud Mode Hors-ligne
Hébergement Vercel + Supabase (Internet) PC serveur ou PC unique (LAN / localhost)
Base de données PostgreSQL managé (Supabase) MySQL / MariaDB portable, embarqué
Internet requis Oui Non — aucune dépendance réseau
Souveraineté données Hébergée chez un tiers de confiance 100 % chez le client, rien ne sort
Code métier Strictement identique — un seul code, deux déploiements

● Le mode hors-ligne en 3 configurations

① Standalone — 1 PC

Tout sur un seul poste (localhost). Idéal pour un petit commerce ou un point de vente unique.

② Serveur LAN — multi-postes

1 PC serveur centralise les données, N PC clients s'y connectent. Idéal pour un magasin multi-postes.

③ Client LAN — PC léger se connectant au serveur (poste de saisie supplémentaire). Le client final n'a rien à installer : l'installeur Windows embarque base de données, runtimes et application.

5 · Sécurité, roadmap & synthèse
StockApp — Présentation plateforme

Sécurité, conformité et perspectives

La plateforme intègre dès sa conception la sécurité des données, la traçabilité des actions et la maîtrise des sauvegardes.

● Sécurité & conformité

  • Authentification par utilisateur, mots de passe hachés (SHA-256).
  • Profils différenciés (ADMIN / USER) avec gestion des permissions.
  • Souveraineté des données : en mode offline, aucune donnée ne sort du site du client.
  • Sauvegardes automatisables — planification quotidienne, purge des anciens dumps, restauration maîtrisée.
  • Pare-feu maîtrisé — ouverture des ports uniquement sur les profils réseau Privé / Domaine.
✅

Points forts actuels

Couverture fonctionnelle large et cohérente · double déploiement cloud / offline opérationnel · génération PDF professionnelle · multi-tenant et multi-postes.

🧭

Pistes d'évolution

Synchronisation cloud ↔ offline (réplication planifiée) · application mobile native · tableaux de bord analytiques avancés · API publique pour intégrations comptables.

● Limitations connues

Point d'attentionExplication
Pas de synchro auto cloud ↔ localChaque installation est indépendante (synchro = évolution future).
Mode LAN = serveur alluméLes clients ne travaillent que si le PC serveur reste sous tension.
Récupération mot de passe offline manuellePar conception (pas d'Internet = pas d'e-mail automatique).
